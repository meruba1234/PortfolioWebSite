プログラミング

Python は import 済みモジュールを再読込しない — 常駐プロセスは再起動が要る

背景

「ソースコードを直したのに、動かしてみると挙動が前のまま変わらない」—— これはプログラミングを始めると必ず一度は踏む落とし穴だ。特に、起動しっぱなしのサーバや、バックグラウンドで動き続けるジョブワーカー、あるいは REPL や Jupyter でコードをいじっているときに起きやすい。

「保存したのに」「pull したのに」なぜ古い動きのまま？ その答えは、 Python がモジュールをどう扱うかを知ると腑に落ちる。

sys.modules というキャッシュ

Python は、一度 import したモジュールを sys.modules という辞書にキャッシュする。 2 回目以降の import は、ファイルを読み直すのではなく、このキャッシュから即座に返す。おかげで import は速いのだが、副作用として プロセスが起動している間、そのモジュールのコードは初回に読んだ時点で固定される。

import sys

import my_module            # 1回目: ファイルを読んでキャッシュに登録
import my_module            # 2回目以降: sys.modules から返すだけ（ファイルは読まない）

print("my_module" in sys.modules)   # True — キャッシュされている

つまり、プロセスが動いている裏でソースファイルを差し替えても、すでに起動しているプロセスは sys.modules の古いオブジェクトを使い続ける。ディスク上のファイルと、メモリ上で動いているコードは別物になっている、というわけだ。

だから常駐プロセスは「再起動」が要る

この性質が効いてくるのが、長時間動き続けるプロセスだ。

  • 常駐 Web サーバ
  • キューを処理し続けるジョブワーカー
  • 起動しっぱなしの REPL / Jupyter カーネル

これらは一度立ち上がると、sys.modules に読み込んだコードをずっと握り続ける。そのため、git pull や cp でファイルを新しくしても、 プロセス側は何も変わらない。反映するには、プロセスやワーカーを再起動して、 sys.modules を空の状態から作り直させる必要がある。

# ファイルを差し替えただけでは反映されない
git pull

# プロセス（ワーカー）を再起動して初めて新しいコードが読み込まれる
systemctl restart my-worker      # 例: サービスとして常駐している場合

「デプロイ = ファイル更新 + プロセス再起動」がワンセット、と覚えておくとよい。ファイルを置き換えるだけの手順は、デプロイの半分しか終わっていない。

importlib.reload の限界

「再起動せずにモジュールだけ読み直したい」場合、importlib.reload() がある。ただしこれは万能ではなく、むしろ限界を知って使うべき道具だ。

import importlib
import my_module

importlib.reload(my_module)      # my_module のソースを読み直す

reload には次のような落とし穴がある。

  • 生成済みのインスタンスは古いまま。reload はモジュールオブジェクトを更新するが、すでに作られた古いクラスのインスタンスは、古い定義を持ち続ける。
  • from x import y で束縛済みの名前は更新されない。 y は import した時点の古いオブジェクトを指したままになる。 reload するなら import x してから x.y の形で参照する必要がある。
  • 依存モジュールは自動では reload されない。 A が B を import していて B を直しても、A を reload しただけでは B は古いまま。
# これは危険: y は古いオブジェクトに束縛されたまま
from my_module import y
importlib.reload(my_module)      # my_module は更新されるが…
# ここでの y は依然として古い定義を指している

こうした落とし穴のせいで、reload は「状態が絡まない小さなモジュールを、対話環境で手早く試す」程度が現実的な用途になる。本番の常駐プロセスをきれいに更新したいなら、素直に再起動するのが確実だ。

確認・テストは「再起動後」に

もう一つ大事なのが、疎通確認やテストは再起動を済ませてから行うという順番だ。ファイルを直した直後、まだ古いコードを握ったプロセスに対してテストを投げると、「直したはずのコード」ではなく「古いコード」を検証してしまう。うまく動いても動かなくても、その結果は当てにならない。

手順としては次の順を守る。

  1. コードを直す
  2. プロセス / ワーカーを再起動する
  3. それから動作確認・テストを行う

なお、構成によっては再起動が要らないケースもある。たとえば「ジョブを実行するたびに最新コードを pull して新しいプロセスで走らせる」タイプのワーカーなら、実行ごとに最新が読み込まれるので、明示的な再起動は不要になる。自分の使っているジョブ基盤がどちらの方式かは、worker / scheduler の挙動ノートで確認しておくとよい。

まとめ

  • Python は import 済みモジュールを sys.modules にキャッシュし、プロセスが動いている間はそのコードを握り続ける。
  • ファイルを差し替えても常駐プロセスには反映されない。反映にはプロセス / ワーカーの再起動が必要（pull や cp だけでは不十分）。
  • importlib.reload() はあるが、生成済みインスタンス・from import 済みの名前・依存モジュールは追従しないため万能ではない。
  • 疎通確認・テストは再起動後に行う。さもないと旧コードを検証してしまう。
