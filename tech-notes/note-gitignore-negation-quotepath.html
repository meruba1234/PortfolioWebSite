プログラミング

.gitignore の否定パターンと既ステージ問題・日本語パス表示

背景

.gitignore を書いていて、こんな場面に出くわした。

  • Excel ファイルは基本コミットしたくないので *.xlsx で全部除外した。でも templates/ に置いた雛形の xlsx だけは Git で管理したい。「全部除外、でも一部だけ復活」をどう書くか。
  • すでに git add してコミット済みのファイルを、後から .gitignore に足したのに一向に無視されない。
  • git status すると日本語のファイル名が "\346\227..." のような数字の羅列で表示されて読めない。

これらは Git を使っていると誰でもぶつかる定番の落とし穴なので、まとめて整理しておく。

否定パターン ! で一部だけ追跡に戻す

.gitignore は「除外ルール」を並べる場所だが、行頭に ! を付けると「このパターンだけは除外を取り消す（＝追跡する）」という否定パターンになる。

# xlsx は全部無視
*.xlsx

# ただし templates 配下の xlsx だけは追跡する
!templates/*.xlsx

ポイントは後に書いたルールが勝つこと。先に *.xlsx で広く除外し、後ろの !templates/*.xlsx で一部を拾い直す、という順序が必要。順番を逆にすると否定が先に打ち消されて効かない。

もう一つの罠がパターンの書き方のズレ。単数・複数、サブパスの指定を間違えるとマッチしない。

*.xlsx
!templates/*.xlsx        # OK: templates 直下の xlsx にマッチ
!template/*.xlsx         # NG: フォルダ名が違う（単数/複数の取り違え）
!*.xlsx                  # 意図不明: 結局全部復活してしまう
!templates/**/*.xlsx     # templates 配下を再帰的に拾いたいならこう

除外パターンと否定パターンで同じ粒度・同じパスを指しているか、必ず突き合わせて確認する。

重要な制約: 親ディレクトリごと除外していると復活できない

否定パターンには大きな制約がある。親ディレクトリそのものを除外していると、その中のファイルを ! で個別に復活させることはできない。

# NG パターン: build ディレクトリごと除外
build/
!build/keep.txt          # これは効かない

理由は、Git がディレクトリを除外と判定した時点でその中身を一切走査しないから。ディレクトリごとスキップされるので、中の keep.txt にはそもそも否定ルールを評価する機会が回ってこない。

復活させたいファイルがあるなら、ディレクトリ自体は除外せず、中のファイルパターンで除外する。

# OK パターン: ディレクトリは除外せず、中身をパターンで除外
build/*
!build/keep.txt          # これなら効く

build/ と build/* は見た目が似ているが挙動が決定的に違う。build/* は「build の中身」を除外するだけで build ディレクトリ自体は走査対象に残るので、否定パターンが評価される。

既に追跡中のファイルは .gitignore では消えない

.gitignore は「まだ追跡していないファイル」に対して効くルール。すでに git add 済み（index に載っている）ファイルは、後から .gitignore に書いても無視されず、変更するたびに差分として出続ける。

追跡から外すには、index（ステージ）から明示的に落とす必要がある。

# ファイル自体は残しつつ、Git の管理からだけ外す
git rm --cached path/to/config.xlsx

# ディレクトリまるごとなら -r
git rm --cached -r build/

--cached を付けるとワーキングツリーのファイルは消さず、index からだけ削除する。この後 .gitignore に追記してコミットすれば、以降は無視されるようになる。--cached を付け忘れると実ファイルまで消えるので注意。

Excel の一時ロックファイルを無視する

Excel でブックを開くと、同じフォルダに ~$ブック名.xlsx のような一時ロックファイルが生成される。これがコミット対象に紛れ込むと邪魔なので、まとめて無視しておく。

# Office の一時ロックファイル
~$*

~$ で始まるファイルは Word / Excel / PowerPoint 共通の一時ファイルなので、~$* の1行で一括除外できる。

日本語パスが化けて見えるときは quotepath

Git はデフォルトで、非 ASCII のパス（日本語ファイル名など）を8進エスケープで表示する。

$ git status
	"\346\227\245\346\234\254\350\252\236.txt"

これは壊れているわけではなく、core.quotepath という設定が既定で有効なため。無効にすれば日本語がそのまま出る。

# その場限りで無効化（このコマンド1回だけ）
git -c core.quotepath=false status

# 恒久的に無効化（今後ずっと日本語をそのまま表示）
git config --global core.quotepath false

-c core.quotepath=false はコマンド単位の一時上書き、git config --global は全リポジトリに効く恒久設定。まず -c で試して、気に入ったら --global にする、という使い方が安全。

まとめ

  • ! で除外の一部を復活できる。ただし除外ルールより後ろに書き、パス粒度を除外側と正確に揃える。
  • 親ディレクトリごと除外（build/）していると中のファイルは ! で復活できない。build/* のように「中身」を除外して、ディレクトリ自体は走査対象に残す。
  • .gitignore は既追跡ファイルには効かない。git rm --cached <file> で index から外す（--cached で実ファイルは残す）。
  • Office の一時ロックファイルは ~$* で一括無視。
  • 日本語パスが8進エスケープで化けたら core.quotepath=false。一時なら -c、恒久なら git config --global。
