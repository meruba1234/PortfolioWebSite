Web技術

DevTools の Network タブで「本命のリクエスト」を特定する

背景

Web 画面のボタンを押すと帳票 (PDF) が出てくる、といった処理を自動化したいとき、「その裏でどんな API がどんなパラメータで呼ばれているのか」を知りたくなる。ブラウザの DevTools (F12) の Network タブ を開けば、画面から飛んでいる通信はすべて一覧に流れてくる。

ところが実際に開いてみると、目的の通信がなかなか見つからない。理由は、多くのサイトに行動解析／接客ツール (トラッキングタグ) が埋め込まれていて、ページを開いた瞬間・スクロール・クリックのたびに解析サーバへ常時通信しているからだ。 Network タブがこの手のノイズで埋め尽くされ、本命の 1 本が埋もれてしまう。

ここでは、そのノイズをかき分けて目的のリクエストを特定し、コードとして再現するまでの道具立てをまとめる。

ノイズを消す — フィルタで対象ドメインに絞る

まずは表示するリクエストを絞り込む。Network タブ上部のフィルタボックスが主役。

  • 対象ドメイン名で絞る: 業務システムのホスト名の一部 (例: myapp.example.com の myapp や example) をフィルタボックスに入れると、解析系や広告系・Google 系のドメインが一掃され、本命のホストへの通信だけが残る。
  • Fetch/XHR フィルタ: フィルタ行のタブで Fetch/XHR を選ぶと、JavaScript から投げている API 通信だけに絞れる。画像・CSS・フォント・解析ビーコンといった雑多なリソースが消えるので、これだけでもかなりスッキリする。
フィルタボックス:  example        ← このドメインを含む通信だけ表示
種別タブ:          [Fetch/XHR]    ← API 通信だけに絞る

この 2 つを併用すると、解析ツールの騒がしい通信を無視して「業務システムと自分のブラウザの会話」だけを見られる。

本命を捕まえる — 操作した瞬間のリクエストを見る

絞り込めたら、次は目的の操作 (例: 「帳票出力」ボタン) を押す。

  • 押した瞬間に現れる行が本命: ボタンを押した直後に一覧の一番下へ新しく追加されるリクエストが、その操作のトリガーになった通信である可能性が高い。押す前にいったん一覧を眺めておき、押した瞬間に増えた分を見ると特定しやすい。
  • Preserve log を ON にする: ボタンを押すとページが遷移したりリロードが走って Network の記録がリセットされることがある。Preserve log (ログを保持) にチェックを入れておくと、画面遷移をまたいでも記録が消えず、遷移前に飛んだリクエストをあとから確認できる。

ポイント: 「いつ現れたか」で犯人を絞る。操作の前後で一覧の差分を見るのがコツ。

再現する — Copy as fetch / cURL

本命が見つかったら、そのリクエストを右クリックしてコピーする。

  • Copy → Copy as fetch: そのリクエストを JavaScript の fetch() 呼び出しとしてクリップボードにコピーする。URL・メソッド・ヘッダ・ボディがそのまま入っているので、コードに貼って再現できる。
  • Copy → Copy as cURL: 同じ内容を curl コマンドとしてコピーする。ターミナルに貼ればそのまま実行できるので、パラメータやヘッダの中身を調べるのに便利。
# Copy as cURL で得られる形 (イメージ)
curl 'https://example.com/report/output.page' \
  -H 'accept: application/pdf' \
  -H 'cookie: session=...' \
  --data-raw 'reportId=123&format=pdf'

これを見れば「どのパラメータで帳票が決まるのか」「どのヘッダ (Cookie など) が必要なのか」が一目でわかる。自動化するときの入力仕様がここから読み取れる。

実体を確かめる — 先頭バイトで中身を判別する

URL の拡張子や Content-Type が実体と食い違うことがある。最終的な中身はレスポンスの先頭バイト (マジックナンバー) で確かめるのが確実。

  • PDF なら %PDF- で始まる: レスポンスの先頭が %PDF- であれば、拡張子が何であれ中身は PDF バイナリ。
  • 拡張子に惑わされない: .page のようなサーバサイドの拡張子 (サーバ側で動的に生成するページを表す) でも、実際には PDF バイナリや HTML を返していることがある。 URL の見た目ではなく、返ってきた中身で判断する。
先頭バイト        実体
%PDF-             PDF
PK (0x50 0x4B)    ZIP / xlsx / docx など (ZIP コンテナ)
<!DOCTYPE / <html HTML
{" または [       JSON

コードで取得したときは、レスポンス本文の先頭数バイトをそのまま確認すれば、保存すべき拡張子や後続処理を正しく選べる。

まとめ

  • サイトには解析／接客ツールが埋め込まれ、Network タブは常時ノイズで埋まる。
  • ノイズを消す: フィルタボックスに対象ドメイン名を入れ、Fetch/XHR で API に絞る。
  • 本命を捕まえる: 操作した瞬間に増える行を見る。Preserve log で遷移をまたいでも記録を残す。
  • 再現する: 右クリック → Copy as fetch / Copy as cURL でコード・コマンド化し、パラメータとヘッダを調べる。
  • 実体を確かめる: 拡張子ではなくレスポンスの先頭バイトで中身を判別する (PDF なら %PDF-)。

画面の裏で何が起きているかは、Network タブの絞り込みと「操作した瞬間」への注目でたいてい突き止められる。あとはそれをコピーして再現し、中身をバイトで確かめれば、自動化の入り口に立てる。
