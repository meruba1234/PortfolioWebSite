プログラミング

標準出力のバッファリング — バックグラウンド実行で print が出ない

背景

スクリプトをバックグラウンドで動かして、ログをファイルに残そうとしたときのこと。

python worker.py > worker.log 2>&1 &

処理は明らかに走っている（CPU も使っているし、後で結果ファイルもできる）のに、 worker.log を開いても中身が空。しばらく待ってようやく大量の行がドバッと出る。あるいはプロセスが終わるまで一切出てこない。

「print を書いたのに出ない＝コードのバグ？」と疑ってログの位置を直したり、 print を増やしたりして時間を溶かしがちだが、これは多くの場合コードのせいではない。犯人は 標準出力のバッファリング という仕組みである。

なぜ端末とパイプで挙動が違うのか

print した文字は、実はすぐには外に書き出されていない。いったんプログラム内部の「バッファ（ためておく箱）」に貯められ、ある条件を満たしたタイミングでまとめて出力先に流される。

このバッファの流し方（＝いつ吐き出すか）が、出力先が何かによって自動で切り替わる。

  • 出力先が 端末（TTY） のとき → 行バッファ 改行が来るたびに吐き出す。だから対話的に実行すると print が即座に画面に出る。
  • 出力先が パイプ・リダイレクト・ファイル のとき → ブロックバッファ 箱が一杯（数 KB 単位）になるまで貯め込み、一杯になった時点でまとめて吐き出す。一杯にならなくても、プロセスが正常終了するときには残りを吐き出す（フラッシュする）。

つまり、端末に直接出すときは軽快に流れて見えるのに、 > file.log やパイプ | tee を挟んだ瞬間に「箱が一杯になるまで沈黙」へと切り替わる。これが「プロセスは動いているのにログが空」の正体である。バックグラウンド実行・パイプ処理・別プログラムからのサブプロセス起動で頻出する。

なぜこんな仕様かというと、出力を1文字ずつ書き出すのは遅く、まとめて書いた方が効率が良いから。端末は「人が見るので即応性優先」、ファイルやパイプは「機械が受けるので効率優先」と、用途に合わせて既定値を変えている。

対処法

出力先がファイル・パイプでも即座に吐き出させたい、という指定をすればよい。方法は複数ある。

1. 起動時に unbuffered モードにする（-u）

一番手軽で確実。Python を -u 付きで起動すると、バッファリングを無効化して即書き出しになる。

python -u worker.py > worker.log 2>&1 &

スクリプト側を一切いじらず、起動コマンドだけで直せるのが利点。バックグラウンドジョブやサービス化するときはこれを既定にしておくと事故らない。

2. print のたびにフラッシュする（flush=True）

特定の print だけ確実に出したいとき。

print("処理を開始しました", flush=True)

flush=True は「この print はためずに今すぐ吐き出せ」という指示。ループの進捗表示など、リアルタイムに見たい行だけ付ける使い方もできる。

3. stdout を行バッファに設定し直す

スクリプトの先頭で一度だけ設定すれば、以降の print は全部行バッファ扱いになる。

import sys
sys.stdout.reconfigure(line_buffering=True)

これを入れておけば、出力先がファイルでも端末のときと同じ「改行ごとに吐き出す」挙動になる。

stderr という抜け道

もう一つ知っておくと便利なのが、標準エラー出力（stderr）は通常バッファされないという点。

print は既定で標準出力（stdout）に出るが、エラーや警告は stderr に出すのが慣習で、 stderr は「異常はすぐ見せたい」ため即書き出しになっている。

import sys
print("進捗: 100件処理", file=sys.stderr)

リアルタイム性がどうしても欲しいログを stderr に回す、という手が使える。ただし本来 stderr はエラー用なので、通常ログまで全部 stderr に流すのは行儀が良くない。基本は -u や flush=True で stdout 側を直し、stderr はあくまで補助的な逃げ道と考えるとよい。

まとめ

  • 標準出力は、出力先が端末なら行バッファ、ファイル・パイプならブロックバッファに自動で切り替わる。
  • ブロックバッファでは print してもすぐには出ず、箱が一杯になるかプロセス終了時にまとめて出る。これが「動いているのにログが空」の正体。
  • 対処は python -u（起動時に無効化）、print(..., flush=True)（都度吐き出し）、 sys.stdout.reconfigure(line_buffering=True)（行バッファ化）のいずれか。
  • stderr は通常バッファされないので、即時性が要るログの逃げ道に使える。
  • ログが出ないときは、コードのバグより先に バッファリングを疑う と早く解決できる。
