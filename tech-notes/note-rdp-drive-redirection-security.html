セキュリティ

RDPのドライブ共有はなぜ危険か：侵害済み接続先からローカルPCを守る

はじめに

リモートデスクトップ（RDP）は画面と入力だけでなく、設定によって手元PCのドライブ、クリップボード、プリンターなども接続先と共有する。接続先が侵害されている場合、この便利な経路がローカルPCへの読み書き経路になり得る。

この記事では、2026年10月に公表された「お名前.com デスクトップクラウド」の不正アクセス事案を入口に、RDPドライブリダイレクト、Active Directory（AD）の高権限管理、セッション失効を整理する。

確認済みの事実と推測を分ける

2026年10月24日の公式発表では、次の内容が公表された。

  • 一部の利用者サーバーに不正なプログラムが設置された
  • 影響の可能性があるサーバーは26,739件
  • この数字は侵害や情報取得が確認された件数ではなく、対象となり得る件数
  • サーバー内の取引口座ログイン情報などが取得され、不正利用された可能性がある
  • 個別の取得・不正利用の有無と範囲は調査中

顧客PCへの具体的な侵入経路は確定していない。ここでは事件原因を断定せず、RDPの一般仕様としてローカル資源が接続先から利用可能になる条件を扱う。

RDPは画面転送だけではない

RDPではローカルドライブ、クリップボード、プリンター、スマートカードなどを接続先へリダイレクトできる。Microsoftは、ドライブリダイレクトを有効にすると、リモートコンピューターがローカルドライブ上のファイルを読み書きできると説明している。

接続先からは、環境によって次のような名前で見える。

\\tsclient\C

ローカルのCドライブをインターネット全体へ公開する仕組みではない。RDPセッション内の仮想チャンネルを通じて、接続先からローカル側へファイル操作を要求する。

危険が成立する条件

接続先サーバーが攻撃者に操作されている
  + 利用者がそのサーバーへRDP接続している
  + ドライブリダイレクトが許可されている
  + 攻撃者が利用者のRDPセッションを悪用できる
  = ローカルドライブへ到達する経路が生じ得る

ドライブリダイレクトを無効化すれば、この経路を一つ閉じられる。組織ではクライアント設定だけに依存せず、グループポリシーやMDMで禁止できる。

暗号化だけでは防げない

RDP通信の暗号化は経路上の盗聴や改ざんを防ぐ。しかし、接続先自体が侵害されている場合、暗号化は接続先からの正規形式のファイル要求を止めない。

したがって、通信経路の保護と、接続先の信頼性・共有範囲の最小化は別々に対策する必要がある。

Active Directoryと横展開

ADはユーザー、コンピューター、グループ、権限を一元管理する仕組みであり、利用自体が危険なのではない。問題は高権限アカウントの利用範囲が広すぎる場合である。Domain Adminsなどの資格情報を取得されると、到達性とログオン権限の範囲内で別サーバーへ侵害が広がる可能性がある。

Microsoftは、特権グループのメンバーを最小限にし、管理者アカウントと通常利用アカウントを分け、管理者がサインインできる端末を制限することを推奨している。

パスワードとセッションは別物

侵害後にパスワードを変更しても、既存のログインセッションが直ちに失効するとは限らない。インシデント対応では次をセットで扱う。

  • パスワード・秘密鍵などの資格情報を変更する
  • 既存セッションやトークンを失効させる
  • 多要素認証を有効化する
  • ログイン履歴・取引履歴を確認する
  • 端末とサーバーを調査する

利用者側の対策

  • 不要なドライブ共有とクリップボード共有をオフにする
  • RDPファイルの接続先、発行元、共有項目を確認する
  • 接続先用の認証情報を重要アカウントと使い回さない
  • 侵害が疑われる場合は接続と全セッションを終了する
  • 安全な端末から資格情報を変更し、端末をフルスキャンする

管理者側の対策

  • Domain Adminsなどのメンバーを最小限にする
  • 日常利用と管理作業でアカウントを分ける
  • 管理者のログオン先を管理端末へ限定する
  • 顧客環境、管理環境、通常業務環境をネットワーク分離する
  • 不要なRDPリダイレクトをグループポリシーで禁止する
  • 管理者ログオンとサーバー間通信を監視する
  • 資格情報変更とセッション失効をインシデント手順に含める
