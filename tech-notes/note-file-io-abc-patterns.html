プログラミング

ファイル I/O の3パターン（直接書き / メモリ完結 / 一時ファイル必須）

背景

共有フォルダやリモートストレージ（ネットワーク越しの保存先）へデータを読み書きするとき、「ローカルに一時ファイルを作るべきか、それとも作らずに直接やりとりできるか」で毎回迷いがちだ。

この判断を場当たり的にやると、不要な一時ファイルを作ってゴミが残ったり、逆に一時ファイルが必要な場面でメモリ上だけで処理しようとして詰まったりする。

そこで「一時ファイルの要否」を軸に A / B / C の3パターン に分類しておくと、新しい処理を書くたびに設計判断が一瞬で済む。以下にその整理をまとめる。

3パターンの整理

パターン中身一時ファイル代表シーン
A: 直接書き文字列・バイト列を組み立てて、そのままリモートへ write不要小さいテキスト、CSV、ログ 1 本など
B: メモリ完結io.BytesIO などメモリ上のバッファで組み立てて read/write不要（ディスクに触れない）xlsx / zip をメモリ内で生成して転送
C: 一時ファイル必須ローカルに実ファイルを一度書き出してから扱う必須ライブラリ/外部プロセスが「パス」しか受け付けない

A: 直接書き

データが小さく、そのまま送れるならこれが一番シンプル。余計なオブジェクトも後始末も要らない。

# 文字列をそのままリモートへ
with open(remote_path, "w", encoding="utf-8") as f:
    f.write("col1,col2\n1,2\n")

B: メモリ完結（BytesIO）

ライブラリが「ファイルオブジェクト（ストリーム）」を受け付けるなら、ディスクを経由せずメモリ上で組み立てられる。一時ファイルの作成も削除も不要になる。

import io
from openpyxl import Workbook

buf = io.BytesIO()
wb = Workbook()
wb.save(buf)          # パスではなくストリームに保存できる
buf.seek(0)
upload(buf.getvalue())  # バイト列としてリモートへ

C: 一時ファイル必須

問題は「パスしか受け付けない」相手。ここは B にできず、必ずローカルの実ファイルが要る。

代表例:

  • ブラウザ自動化のダウンロード — ダウンロードを実行するのはブラウザ自身であり、ブラウザはローカルにファイルを書き出す。だから受け取り側は download.save_as("/tmp/xxx.xlsx") のように 保存先パス を渡す形になる。
  • サブプロセス / 外部コマンド — 引数にファイルパスを取る CLI ツールに渡す場合。
  • C 実装のライブラリ API — パス引数しか用意されていないもの。
import tempfile, os

# パスを要求する相手にはローカル実ファイルを渡すしかない
tmp = tempfile.NamedTemporaryFile(suffix=".xlsx", delete=False)
tmp.close()
try:
    download.save_as(tmp.name)   # ← パスが必須
    with open(tmp.name, "rb") as f:
        upload(f.read())         # 読み直してリモートへ
finally:
    os.remove(tmp.name)          # 後始末は必ず

判断軸

どのパターンにするかは、次の3点を順に確認すれば決まる。

  1. 使うライブラリはパスを要求するか、ストリームも受け付けるか
  • パスしか無理 → C
  • ストリームOK → A か B へ
  1. データはメモリに載るサイズか
  • 十分小さい → A / B
  • 巨大 → C（後述）
  1. ネットワーク越しか
  • リモート直書きが可能なら A、メモリで組んで転送なら B

ざっくり言えば「パス必須なら C、そうでなければサイズを見て A か B」。

サイズとメモリの注意

B（BytesIO）は手軽だが、すべてメモリに載る ことを忘れてはいけない。

  • 巨大ファイルや、複数ファイルをまとめて zip する処理を BytesIO でやると、内容がまるごと RAM を占有し OOM（メモリ枯渇） を起こしうる。
  • こういうときは C にして物理的な一時ファイルを使う方が安全。 OS のページキャッシュが必要な部分だけ効率よくメモリに載せてくれるので、巨大でもメモリを食いつぶしにくい。

つまり「小さい＝B で身軽に」「大きい・大量＝C で OS に任せる」と覚えておくとよい。

後始末を忘れない

C の一時ファイルは、使い終わったら 必ず消す。消し忘れは共有ディスクやローカルにゴミを残す。

  • try / finally で確実に os.remove() する
  • あるいは context manager を使う
  • tempfile.NamedTemporaryFile を使えば衝突しない一時名を自動で用意してくれる（delete=False で開いた場合は自分で消す責任が残る点に注意）
import tempfile

# with を抜けると自動で削除される（ただしパスを外部プロセスに渡す間は
# ファイルが開かれたままになる点に注意。Windows では別プロセスが開けないこともある）
with tempfile.NamedTemporaryFile(suffix=".csv") as tmp:
    ...  # tmp.name を使う
# ここで自動削除

まとめ

  • リモート I/O は 一時ファイルの要否 で A（直接）/ B（メモリ）/ C（一時ファイル必須）に分ける。
  • 分岐の起点は「ライブラリがパスを要求するか」。パス必須なら問答無用で C。
  • ストリーム対応なら、サイズで A/B と C を選ぶ。巨大・大量は BytesIO を避けて C にし、OS のキャッシュに任せる。
  • C を選んだら 後始末（削除） をセットで設計する。try/finally か context manager で確実に。
