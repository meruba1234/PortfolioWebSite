PythonVBA金額計算移植

Python Decimal と VBA の丸め・整数化の差分

何を学んだか

販売管理の金額計算を Python に移植するとき、計算式が同じに見えても、丸め処理と整数化のタイミングが違うだけで 1 円単位の差が出ることがある。

特に注意する点は次の3つ。

  • RoundEX のような丸め関数の戻り値が、本当に小数部のない Decimal になっているか。
  • VBA の暗黙的な Integer 変換と Python の int() は、同じ丸め規則ではない。
  • 金額同士の差分を出す場合は、VBA と同じ段階で整数化してから減算する必要がある。

今回の論点

VBA 側では、概念的には次の順序で計算していた。

' Step 1: Decimal 型で計算
genKin = mfFull9(原価 * 総数量)

' Step 2: RoundEX で丸めてから mf9 で整数化
原価金額 = mf9(RoundEX(genKin, wMaru, 0))

' Step 3: Decimal 型で計算
kin = mfFull9(単価 * 総数量)

' Step 4: RoundEX で丸めてから mf9 で整数化
金額 = mf9(RoundEX(kin, wMaru, 0))

' Step 5: 整数同士を減算して Decimal 型に
arrKin = mfFull9(金額 - 原価金額)

' Step 6: mf9 で整数化
粗利金額 = mf9(arrKin)

Python 側では、次のような処理になっていた。

genka_kingaku = self.round_ex(detail.genka * detail.qty, maru_kbn, 0)
genka_kingaku_int = int(genka_kingaku)

uriage_kingaku = self.round_ex(detail.tanka * detail.qty, maru_kbn, 0)
uriage_kingaku_int = int(uriage_kingaku)

arari_kingaku = uriage_kingaku_int - genka_kingaku_int

見た目は近いが、mf9() に渡す時点の VBA 暗黙型変換と、Python の int() の意味を分けて考える必要がある。

VBA と Python の整数化の違い

Python の int()

Python の int(Decimal) は、小数部を 0 方向に捨てる。

int(Decimal("12.9"))   # 12
int(Decimal("-12.9"))  # -12

これは四捨五入ではない。

VBA / VB.NET の Integer 変換

VBA / VB.NET で小数を Integer に暗黙変換すると、銀行丸め、つまり偶数丸めになるケースがある。

例:

CInt(12.5) ' 12
CInt(13.5) ' 14

そのため、12.5 や 13.5 のような値が整数化時点で残っている場合、Python の int() とは結果が変わる。

ただし、RoundEX 後なら必ず差が出るわけではない

RoundEX(value, wMaru, 0) が正しく小数第0位へ丸めていて、戻り値が Decimal("12") や Decimal("12.0") のように実質整数であれば、VBA の整数変換でも Python の int() でも結果は同じになる。

int(Decimal("12.0"))  # 12

したがって、ズレが出た場合は次を確認する。

  • round_ex(..., keta=0) の戻り値に小数部が残っていないか。
  • Decimal("12.000000001") のような微小な誤差が入り込んでいないか。
  • detail.genka、detail.tanka、detail.qty が float 由来で Decimal 化されていないか。
  • VBA と Python で「丸めてから整数化」「整数化してから減算」の順序が一致しているか。

Decimal で注意すること

Decimal を使っていても、元データが float から来ていると、すでに浮動小数点誤差を含んだ値を Decimal 化してしまうことがある。

避けたい例:

Decimal(0.1)

望ましい例:

Decimal("0.1")

CSV や DB から読む金額・数量は、可能な限り文字列から Decimal に変換する。

切り分け手順

金額が 1 円ずれるときは、最終結果だけを比べず、VBA と Python の中間値を同じステップで比較する。

  1. 原価 * 総数量 の結果を比較する。
  2. RoundEX(..., wMaru, 0) の結果を比較する。
  3. mf9() または int() 後の原価金額を比較する。
  4. 売上金額も同じ手順で比較する。
  5. 粗利金額は、丸め前 Decimal 同士ではなく、VBA と同じく整数化後の金額同士で減算しているか確認する。

比較ログでは、表示用の文字列だけでなく repr() や as_tuple() 相当の内部表現も見るとよい。

print(value, repr(value), value.as_tuple())

実装方針

VBA の挙動に合わせる場合は、次の方針にする。

  • 金額計算の途中値は Decimal で保持する。
  • round_ex(..., keta=0) の直後に、小数第0位へ確定していることを保証する。
  • 整数化のタイミングを VBA と合わせる。
  • 粗利は、売上金額と原価金額をそれぞれ整数化した後に減算する。
  • DB 保存直前だけでなく、VBA が整数化している箇所でも同じ意味の整数化を行う。

覚えておく結論

Decimal を使っているだけでは、VBA と Python の金額計算は一致しない。

一致させるには、次の3点を揃える必要がある。

  • 丸め規則
  • 整数化規則
  • 整数化するタイミング

int() は「整数にする」関数だが、「VBA の Integer 変換と同じ丸めをする」関数ではない。金額計算を移植するときは、丸めと型変換を別の処理として扱う。
