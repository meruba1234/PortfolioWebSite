セキュリティ

SSH 鍵の形式（PuTTY .ppk と OpenSSH）と変換・エージェント

背景

Windows で PuTTYgen を使って作った SSH 鍵（.ppk）を、そのまま git bash や WSL で使おうとすると弾かれる。逆に、git bash で作った id_ed25519 を PuTTY に読ませようとしても開けない。これは SSH 鍵の「保存形式」が2系統あり、互いに互換がないためだ。片方で作った鍵をもう片方で使うには変換が必要になる。ここでは2形式の違い、変換方法、鍵を保持するエージェント、用途の向き、そして基本の運用ルールを整理する。

2つの鍵形式

SSH 鍵の保存形式には大きく2系統ある。

  • PuTTY 独自形式（.ppk = PuTTY Private Key） Windows の PuTTY / PuTTYgen が使う独自形式。1ファイルの中に秘密鍵・公開鍵・コメントなどをまとめて持つ。PuTTY 系ツール以外は基本的に読めない。
  • OpenSSH 形式 git bash・WSL・Linux・macOS が標準で使う形式。~/.ssh/ に秘密鍵（id_ed25519、id_rsa 等）と公開鍵（id_ed25519.pub 等）が別ファイルで置かれる。世の中の SSH サーバやツールが前提にしているのはこちら。

重要なのは、鍵ペアそのもの（数学的な鍵）が違うわけではなく、あくまで「ファイルへの入れ方（フォーマット）」が違うという点。だから中身は同じ鍵のまま、形式だけを変換して相互に使える。

変換方法

PuTTYgen（GUI）で .ppk → OpenSSH

  1. PuTTYgen を起動し、Load で .ppk を読み込む（パスフレーズ付きなら入力）。
  2. メニューの Conversions → Export OpenSSH key を選ぶ。
  3. OpenSSH 形式の秘密鍵ファイルとして保存する（例: id_ed25519）。
  4. 公開鍵は PuTTYgen 画面上部のテキスト欄（ssh-ed25519 AAAA... の一行）をコピーして使う。

逆向き（OpenSSH → .ppk）も、PuTTYgen で Load（OpenSSH 秘密鍵を選ぶ）→ Save private key で .ppk として保存できる。

ssh-keygen（WSL / Linux）で変換

コマンドラインでも変換できる。既存の OpenSSH 秘密鍵から公開鍵を取り出す例:

# 秘密鍵から公開鍵を再生成する（authorized_keys 登録用の一行が得られる）
ssh-keygen -y -f ~/.ssh/id_ed25519 > ~/.ssh/id_ed25519.pub

PuTTY 形式が絡む変換は、putty-tools パッケージの puttygen コマンドが使える。

# .ppk を OpenSSH 秘密鍵に変換する
puttygen my_key.ppk -O private-openssh -o id_ed25519

# OpenSSH 秘密鍵を .ppk に変換する
puttygen id_ed25519 -O private -o my_key.ppk

鍵エージェント（Pageant / ssh-agent）と橋渡し

パスフレーズ付きの秘密鍵を毎回打たずに使うため、鍵をメモリに保持しておく「エージェント」がある。ここも2系統に分かれる。

  • Pageant … PuTTY 系のエージェント。.ppk を読み込んで常駐する。
  • ssh-agent … OpenSSH 系のエージェント。ssh-add で秘密鍵を登録する。
# ssh-agent を起動して鍵を登録する（git bash / WSL）
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

注意点として、git bash の OpenSSH は Pageant を直接は見に行かない。PuTTY 側（Pageant）に鍵を入れているのに git bash から使いたい、という場合は、両者を橋渡しするツール（wsl-ssh-pageant 等）を挟む必要がある。混乱を避けたいなら、git bash / WSL 用には最初から OpenSSH 形式 + ssh-agent で統一してしまうのが素直。

用途の向き

どちらが「正しい」ではなく、やりたいことで向き不向きがある。

  • ワンライナーでリモート実行したい → git bash / WSL の OpenSSH が向く。 ``bash ssh user@host "uptime" # 1コマンド叩いて結果を受け取る `` シェルスクリプトや自動化に組み込みやすい。
  • 対話的に接続したい・Windows GUI で運用したい → PuTTY が向く。セッション設定を GUI で保存・再利用でき、Windows 単体で完結する。

パーミッションと公開鍵登録の基本

形式や用途に関わらず、SSH 鍵運用の基本は共通。

  • 秘密鍵は絶対に共有しない・送らない。手元だけに置く。共有していいのは公開鍵（.pub）だけ。
  • 秘密鍵のパーミッションは厳しく。OpenSSH は権限が緩い秘密鍵を安全上の理由で拒否する（600 = 所有者のみ読み書き、でないと弾かれることが多い）。 ``bash chmod 600 ~/.ssh/id_ed25519 chmod 700 ~/.ssh # ~/.ssh 自体も所有者のみに ``
  • 公開鍵は接続先サーバの ~/.ssh/authorized_keys に登録する。ここに載っている公開鍵に対応する秘密鍵を持っていれば認証が通る、という仕組み。 ``bash # 公開鍵を接続先の authorized_keys に追加する（便利コマンド） ssh-copy-id user@host ``

まとめ

  • SSH 鍵の保存形式は PuTTY 独自の .ppk と OpenSSH 形式の2系統あり、互換がないので相互変換が要る。鍵そのものは同じで「入れ物」が違うだけ。
  • 変換は PuTTYgen（GUI: Load → Export OpenSSH key） か、puttygen / ssh-keygen コマンドで行う。
  • エージェントも2系統。PuTTY = Pageant、OpenSSH = ssh-agent。git bash の OpenSSH は Pageant を直接見ないので、橋渡しツールが要る場合がある。
  • ワンライナーでのリモート実行なら OpenSSH、対話・GUI 運用なら PuTTY が向く。
  • どちらでも基本は同じ。秘密鍵は共有しない・権限は 600・公開鍵を相手の authorized_keys に登録する。
