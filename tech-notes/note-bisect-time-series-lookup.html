プログラミング

bisect で「基準日以前の最新」を高速に選ぶ（二分探索）

背景

「価格改定履歴」や「税率の変更履歴」のように、ある値が時点によって切り替わるデータを扱う場面は多い。たとえば適用開始日ごとに単価が並んだ履歴があり、「2026-07-01 時点で有効な単価はいくつか」を求めたい。

これは「指定日以前で、最も新しいレコードを 1 件選ぶ」という操作になる。履歴を先頭から順に見ていく線形スキャンでも書けるが、履歴が長くなると 1 件引くたびに全件を舐めることになり遅い。履歴が適用日でソート済みなら、二分探索（bisect）を使って O(log n) で一発で選べる。

二分探索とは

ソート済みの列に対して、探索範囲を毎回半分に絞り込みながら目的の位置を見つける手法。 n 件を順番に見る線形探索が O(n) なのに対し、二分探索は O(log n)。たとえば 100 万件でも約 20 回の比較で目的地に到達できる。

Python では標準ライブラリ bisect がこれを提供する。要素そのものを探すのではなく、「ソート順を保ったままなら、この値はどこに挿入されるか（挿入位置）」を返すのがポイント。

bisect_right / bisect_left と「添字 -1」で直近を引く

有効日でソートされた日付リストに対し、bisect_right(dates, d) は「d を挿入しても昇順が保たれる一番右の位置」を返す。この戻り値から 1 を引くと、「d 以下（d を含む）の最後の要素」の添字になる。これがまさに「指定日以前の直近レコード」だ。

from bisect import bisect_right

# 適用開始日でソート済みの価格改定履歴（同じキーの商品に対する履歴）
history_dates  = ["2026-01-01", "2026-04-01", "2026-07-01"]
history_prices = [       100,          120,          135  ]

def price_on(target_date: str) -> int | None:
    # target_date 以下で最後の要素の添字を得る
    idx = bisect_right(history_dates, target_date) - 1
    if idx < 0:
        return None  # 履歴の開始より前 = 有効な値なし
    return history_prices[idx]

print(price_on("2026-06-15"))  # -> 120  (04-01 適用ぶんが有効)
print(price_on("2026-07-01"))  # -> 135  (当日ちょうどの改定を含む)
print(price_on("2025-12-31"))  # -> None (履歴開始前)

bisect_left と bisect_right は、探索値がリスト内の要素とちょうど一致したときの扱いが違う。

  • bisect_right(dates, d): 一致要素の 右側 の位置を返す。-1 すると「d 当日を含む」直近になる。
  • bisect_left(dates, d): 一致要素の 左側 の位置を返す。-1 すると「d より前（当日を除く）」の直近になる。

「改定日当日から新価格を適用する」なら bisect_right、「改定日当日はまだ旧価格」なら bisect_left を使う。境界日をどう数えるかで結果が 1 件ずれるので、仕様（当日を含むか含まないか）を必ず確認してから選ぶ。

key 引数でオブジェクトのリストをそのまま探索する（Python 3.10+）

日付だけの並列リストを別に持たなくても、履歴レコードのリストに対して key= で探索キーを指定できる。

from bisect import bisect_right
from dataclasses import dataclass

@dataclass
class PriceRecord:
    start_date: str
    price: int

# start_date でソート済みであること
history = [
    PriceRecord("2026-01-01", 100),
    PriceRecord("2026-04-01", 120),
    PriceRecord("2026-07-01", 135),
]

def price_on(target_date: str) -> int | None:
    idx = bisect_right(history, target_date, key=lambda r: r.start_date) - 1
    if idx < 0:
        return None
    return history[idx].price

key= は Python 3.10 で追加された。3.9 以前では日付だけを抜き出した別リストを作って探索する。

前提と使いどころ

  • 必ず事前にソート済みであること。 二分探索はソート済みを前提にするので、未ソートのまま使うと誤った結果を返す。取得時に ORDER BY する、または一度だけ sort() しておく。
  • キーごとに履歴を分けて持つと引きやすい。 「得意先 × 商品」のように単価が相手ごとに違うなら、(得意先, 商品) -> ソート済み履歴 の辞書にしておき、キーで履歴を取り出してから二分探索する。全レコードを 1 本の列に混ぜると探索前に絞り込みが必要になる。
  • 同じ履歴を何度も引くなら、辞書化 + ソートの初期コストは一度で済み、以降は 1 件あたり O(log n) で回収できる。

まとめ

  • ソート済みの履歴なら、bisect で「指定日以前の直近レコード」を O(log n) で選べる。線形スキャン O(n) より速い。
  • bisect_right(dates, d) - 1 が「d 当日を含む直近」の添字。bisect_left は当日を除く直近になり、境界の扱いが 1 件ずれる。
  • Python 3.10+ は key= でオブジェクトのリストをそのまま探索できる。
  • 前提は「事前にソート済み」。キーごとに履歴を分けて持つと引きやすい。
  • 価格・単価・税率・各種設定値など「その時点で有効な値を引く」場面に広く効く汎用パターン。
