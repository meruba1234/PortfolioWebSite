データベース

SQL Server にクロスプラットフォーム接続（ODBC Driver 18 / TrustServerCertificate / Linux）

背景

開発は Windows PC で行い、本番は Linux コンテナ（Docker）で動かす、という構成はよくある。このとき、どちらの環境からも同じ SQL Server（同じ DB）に Python から繋ぎたい。理想は「コードは 1 本、環境差はドライバのインストールだけ」で済ませること。

Python から SQL Server へ繋ぐ定番は pyodbc + Microsoft 純正の ODBC ドライバだが、バージョン 18 で暗号化まわりの既定が変わったこと、Linux でのドライバ準備、そして OS による文字コードの挙動差を押さえておくと事故らない。

pyodbc と ODBC ドライバ

Python 側は pyodbc を使い、実際の SQL Server との通信は OS にインストールした ODBC ドライバが担当する。接続文字列の DRIVER=... でどのドライバを使うか指定する。

import pyodbc

conn = pyodbc.connect(
    "DRIVER={ODBC Driver 18 for SQL Server};"
    "SERVER=dbhost,1433;"
    "DATABASE=mydb;"
    "UID=myuser;"
    "PWD=secret;"
)

pyodbc はあくまで Python から ODBC を叩くための薄い層で、「ドライバ本体」は別途 OS にインストールが必要という点を混同しないこと。

Driver 18 は暗号化が既定で必須

ODBC Driver 18 から、既定値が Encrypt=yes（暗号化必須）に変わった。 17 以前は Encrypt=no が既定だったので、17 で動いていた接続文字列を 18 にそのまま持ってくると、証明書検証で弾かれて繋がらないことがある。

社内でよくあるのは、SQL Server が自己署名証明書を使っているケース。このとき、クライアントは証明書チェーンを信頼できないため検証に失敗する。検証を回避するには TrustServerCertificate=yes を付ける。

conn = pyodbc.connect(
    "DRIVER={ODBC Driver 18 for SQL Server};"
    "SERVER=dbhost,1433;"
    "DATABASE=mydb;"
    "UID=myuser;PWD=secret;"
    "Encrypt=yes;"
    "TrustServerCertificate=yes;"
)

注意点として、TrustServerCertificate=yes は「通信自体は暗号化するが、相手の証明書が本物かは確認しない」という妥協。これは社内 LAN で相手が信頼できる前提だから許される。公開ネットワーク越しの接続では中間者攻撃を防げないので使わないこと。本来は正規の証明書を入れて検証させるのが正道。

Linux コンテナでは msodbcsql18 を入れる

Linux でも Microsoft が ODBC ドライバを配布している。パッケージ名は msodbcsql18（Driver 18 の実体）で、これと unixODBC（ODBC ランタイム）を入れれば、Windows とまったく同じ接続文字列で pyodbc から繋げる。

Debian/Ubuntu 系コンテナなら、Microsoft のリポジトリを追加してからインストールするイメージ（apt の場合の例）:

# Microsoft パッケージリポジトリを追加した上で
RUN ACCEPT_EULA=Y apt-get install -y msodbcsql18 unixodbc

ライセンス同意のため ACCEPT_EULA=Y を渡す必要がある点だけ注意。これでコンテナ内の pyodbc からも DRIVER={ODBC Driver 18 for SQL Server} が解決できるようになる。

接続文字列はドライバ優先順位で組む

環境によって入っているドライバのバージョンが違う（Driver 18 のマシンもあれば 17 しかないマシンもある）ことを想定し、優先順位で探して組むと環境差に強い。

import pyodbc

def pick_driver():
    installed = pyodbc.drivers()
    for name in ("ODBC Driver 18 for SQL Server",
                 "ODBC Driver 17 for SQL Server"):
        if name in installed:
            return name
    raise RuntimeError("SQL Server 用 ODBC ドライバが見つかりません")

driver = pick_driver()
conn = pyodbc.connect(
    f"DRIVER={{{driver}}};"
    "SERVER=dbhost,1433;"
    "DATABASE=mydb;"
    "UID=myuser;PWD=secret;"
    "Encrypt=yes;TrustServerCertificate=yes;"
)

pyodbc.drivers() でインストール済みドライバ名の一覧が取れるので、 Driver 18 を最優先、無ければ 17 …とフォールバックする。 f-string 内で {ODBC Driver 18 ...} の波括弧をリテラルとして出すには {{ }} とエスケープする点に注意。

OS 差の注意：数値は合うが I/O 層で差が出る

同じコード・同じ接続文字列でも、文字コード（codec）まわりは OS で挙動が変わることがある。ドライバやロケールの既定エンコーディングが Windows と Linux で異なるため、日本語などマルチバイト文字の読み書きで文字化けやデコードエラーが Linux 側だけで起きる、といったケースがある。

ポイントは、数値集計の結果が完全一致していても、文字列 I/O 層では差が出得る ということ。「金額の合計は Windows も Linux も一致したから移植 OK」ではなく、文字列カラムの取り込み・出力も別途確認する必要がある。 codec の具体的な設定（setencoding / setdecoding 等）は別ノートで詳述する。

まとめ

  • Python → SQL Server は pyodbc + Microsoft 純正 ODBC ドライバ。DRIVER={ODBC Driver 18 for SQL Server} を接続文字列に書く。
  • Driver 18 は既定で Encrypt=yes。自己署名証明書の社内 DB には TrustServerCertificate=yes を付けて検証を回避する（社内 LAN 前提の妥協。公開網では使わない）。
  • Linux コンテナは msodbcsql18 + unixODBC を入れれば Windows と同じ接続文字列で繋がる。
  • ドライバは優先順位（18 → 17 …）で pyodbc.drivers() から選ぶと環境差に強い。
  • 数値が一致しても文字コードは OS で挙動が変わる。I/O 層の検証は別途行う。
