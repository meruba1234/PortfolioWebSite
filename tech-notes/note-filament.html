Web技術

Filament 用語と構造ガイド

Filamentとは

LaravelのPHPフレームワーク上で動く管理画面フレームワーク。 Livewire（サーバーサイドでHTMLを生成しリアルタイム更新する仕組み）をベースにしている。素のHTMLを書かなくてもPHPコードだけで管理画面が作れる。

用語の整理：「仕組み」か「部品」か

用語分類一言説明
FilamentフレームワークLaravel用の管理画面フレームワーク（Livewireベース）
パネル仕組み独立したURL空間を持つ画面エリア。社内ポータルは4つある
リソース仕組み1つのDBテーブル(モデル)に対するCRUD画面セット
ページ部品画面1枚。リソースには一覧/作成/詳細/編集の4枚が自動生成される
スキーマ仕組みフォームやInfolistのフィールド定義API（Filament 4からの統一名）
ウィジェット部品ダッシュボードに置ける小さなUI部品（グラフ、お知らせ等）
テーブル部品一覧ページの行・列・フィルタ・ボタンの定義
Infolist部品詳細表示（読み取り専用）のフィールド定義

パネル（Panel）

Filamentで複数の独立したUIエリアを管理する単位。 「アプリケーション全体の区画」と考えるとわかりやすい。

社内ポータルの4つのパネル

パネルIDURL用途
admin/adminユーザー・定数・帳票管理
wms/wms倉庫・在庫・発注・配車
insight/insightレポート・分析ダッシュボード
sales/sales販売管理

各パネルは独立した色設定・テーマ・メニュー構成を持つ。

設定ファイルの場所

app/Providers/Filament/
├── AdminPanelProvider.php
├── WmsPanelProvider.php
├── InsightPanelProvider.php
└── SalesPanelProvider.php

リソース（Resource）

Eloquentモデル（DBテーブル）に対するCRUD画面を自動生成するクラス。 「テーブル1つ分のCRUD」が1リソース。

リソースが自動生成する4つのページ

ページファイル例用途
ListListWarehouses.php一覧・テーブル表示
CreateCreateWarehouse.php新規作成フォーム
ViewViewWarehouse.php詳細表示（読み取り専用）
EditEditWarehouse.php編集フォーム

社内ポータル独自パターン：Schema Factory

通常のFilamentはリソースの中にフォームと詳細表示を別々に書くが、社内ポータルでは fieldsMeta() という独自パターンで1回書けば両方に使い回せる設計。

// WarehouseSchemas.php の中
protected static function fieldsMeta(): array {
    return [
        'basic' => [
            'label' => '基本情報',
            'fields' => [
                ['name' => 'code', 'label' => 'コード', 'type' => 'text', ...],
                ['name' => 'name', 'label' => '倉庫名', 'type' => 'text', ...],
            ],
        ],
    ];
}
// → これ1つからフォーム用とInfolist用が自動生成される

フィールド定義の変更が1ファイルで完結するため、フォームと詳細表示の内容がズレない。

ウィジェット（Widget）

ダッシュボードやページに配置できる再利用可能なUI部品。グラフ、お知らせ表示、統計カードなど。

app/Filament/Wms/Widgets/
├── AnnouncementWidget.php      ← お知らせ表示
├── ReceivingChartWidget.php    ← 入荷チャート
└── ShippingChartWidget.php     ← 出荷チャート

ナビゲーション（サイドメニュー）の仕組み

メニューの表示/非表示は config/filament-navigation.php で一元管理。ロール（役職）ごとに見えるメニューが変わる。

// config/filament-navigation.php
'業務マスタ' => [
    'allowed_roles' => [UserRole::SystemAdmin, UserRole::Manager],
    'items' => [
        ['type' => 'resource', 'resource' => WarehouseResource::class, 'label' => '倉庫マスタ保守'],
    ],
],

全体のアクセスフロー

ブラウザ
  ↓
PanelProvider（パネルID・URLパス・使用リソースの登録）
  ↓
Resource（モデルとの紐付け、4つのページルート定義）
  ↓
Page（List / Create / View / Edit）
  ↓
Schema Factory（fieldsMeta → フォーム・Infolist自動生成）

まとめ

  • パネル = アプリの区画（管理者向け、倉庫向け、など）
  • リソース = テーブル1つ分のCRUD
  • ページ = 画面1枚（一覧・作成・詳細・編集）
  • スキーマ = フォームや詳細表示のフィールド定義
  • ウィジェット = ダッシュボードの小部品
  • テーブル = 一覧画面の列・フィルタ設定

社内ポータルでは「Schema Factoryパターン」でフォームと詳細表示の定義を共通化している（Filament標準ではない独自設計）。
