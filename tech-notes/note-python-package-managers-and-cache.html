プログラミング

Python パッケージマネージャとキャッシュ

背景

Python でライブラリ（pandas, requests など）を使うとき、pip install や uv add でインストールする。このとき 「キャッシュ」 が裏で作られていて、知らないうちに数十 GB を消費していることがある。

PCの容量が逼迫したときに 「キャッシュは消していいのか？」 を判断できるようにするためのノート。

パッケージマネージャの種類

ツール役割キャッシュ場所（Windows）
pip標準のパッケージマネージャC:\Users\<user>\AppData\Local\pip\Cache
uvRust 製の高速版 pip。Astral 社製C:\Users\<user>\AppData\Local\uv\cache
poetry依存解決＋仮想環境管理C:\Users\<user>\AppData\Local\pypoetry\Cache
condaデータサイエンス系で使う別系統C:\Users\<user>\.conda\pkgs

job-repo プロジェクトでは uv を使っている。

キャッシュとは何か

パッケージマネージャがインターネットからダウンロードした wheel ファイル（.whl、Python ライブラリの配布形式）と、ビルド中間生成物の保管庫。

役割

  • 2回目以降のインストールを高速化 する
  • 例: 別プロジェクトで同じ pandas==2.2.0 を入れる時、再ダウンロードせずキャッシュから即コピー
  • オフラインでも再インストール可能 にする
  • ネットワーク帯域の節約

キャッシュとインストール先は別

ここが混同しやすいポイント。

┌─────────────────────────────────┐
│ キャッシュ (1か所、共有)              │
│ AppData\Local\uv\cache              │  ← .whl の倉庫
└─────────────────────────────────┘
              ↓ コピー
┌────────────────┐ ┌────────────────┐
│ プロジェクトA      │ │ プロジェクトB      │
│ .venv/             │ │ .venv/             │  ← 実際にimportされるのはこっち
│ └ pandas/          │ │ └ pandas/          │
└────────────────┘ └────────────────┘
  • キャッシュ = ダウンロード済みパッケージの倉庫（消しても動作には無関係）
  • .venv/ = プロジェクトごとの仮想環境、実際に Python が読み込む場所（消すと動かなくなる）

なぜキャッシュは肥大化するのか

  1. バージョン違いを全部キャッシュする
  • pandas==2.2.0 も pandas==2.1.4 も両方残る
  1. ビルドキャッシュ が積み上がる
  • C 拡張のあるパッケージ（numpy, lxml など）はビルド済みバイナリを保存
  1. uv は積極的にキャッシュする設計
  • 高速化のために hardlink で再利用するため、消さない限り溜まり続ける
  1. 古いプロジェクトを消しても、キャッシュは残る
  • .venv を消してもキャッシュは残るので、何度も uv sync していると蓄積

実例: このPCでは uv キャッシュが 22 GB に達していた。

削除して安全な理由

消えるもの

  • ダウンロード済み .whl ファイル（ネットから再取得可能）
  • ビルド中間生成物（再ビルドで再生成可能）

消えないもの（無事）

  • 各プロジェクトの .venv/（実際の動作環境）
  • pyproject.toml、uv.lock（依存定義）
  • インストール済みのコマンド（pytest など）

副作用

  • 次回 uv sync が 少し遅くなる（ネット経由で再ダウンロード）
  • インターネット接続が必要

実害ゼロに近い。公式が uv cache clean というコマンドを用意している こと自体が「定期的に消してOK」という設計思想の表れ。

キャッシュ操作コマンド

uv

uv cache dir       # キャッシュ場所の確認
uv cache clean     # キャッシュ全削除
uv cache prune     # 未使用エントリだけ削除（より安全）

pip

pip cache dir      # 場所
pip cache list     # 中身一覧
pip cache purge    # 全削除
pip cache remove pandas  # 個別削除

判断フロー（容量が足りないとき）

PCの空き容量が少ない
        ↓
AppData\Local\uv や AppData\Local\pip が大きい？
        ↓ Yes
動作中のアプリへの影響なし（.venv は別物）
        ↓
削除実行 (uv cache clean)
        ↓
空き容量回復
        ↓
次にプロジェクトを動かすときだけ再ダウンロード（数十秒〜数分）

迷う必要なし。キャッシュは消してOK。

関連知識

  • .venv/ を移動・コピーは基本NG — 絶対パスが埋め込まれていて動かない。uv sync で再構築するのが正解
  • uv.lock は必ず Git 管理する — これがあれば誰でも同じ環境を再現できる
  • HDD 圧迫の他の犯人:
  • Docker の vhdx（WSL2仮想ディスク、自動縮小されない）
  • ブラウザのキャッシュ
  • Windows Update の WinSxS、Windows\Installer
  • Outlook の .ost（メールキャッシュ）

まとめ

  • パッケージマネージャの キャッシュ は「ダウンロード済み倉庫」
  • 実際の動作環境（.venv）とは別物 なので削除しても動作に影響しない
  • 容量逼迫時は迷わず削除してよい
  • uv cache clean / pip cache purge が公式コマンド
