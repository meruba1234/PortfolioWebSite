プログラミング

Python の sys.path にディレクトリを追加するとは

背景

job-repo などのプロジェクトで「sys.path に /flows を追加する」という話が出る。これが何をしている操作で、なぜ必要なのかを整理しておくためのノート。

sys.path とは

Python の import 文がモジュールを探すときに見にいく ディレクトリのリスト。標準ライブラリの sys モジュールに入っていて、Python 起動時に自動で組み立てられる。

import sys
print(sys.path)
# ['', 'C:\\Python311\\Lib', 'C:\\Python311\\Lib\\site-packages', ...]

import foo と書くと、Python は sys.path を 上から順に 見ていき、最初に見つかった foo.py または foo/ パッケージを読み込む。

「/flows を追加する」とは

sys.path の検索対象に /flows ディレクトリを加える操作。

例えば /flows/anomaly/flow.py というファイルがあるとき：

import sys
sys.path.insert(0, "/flows")

# これで以下が書けるようになる
from anomaly import flow
from anomaly.scripts import detector

sys.path に /flows が入っていないと ModuleNotFoundError: No module named 'anomaly' になる。

job-repo での文脈

リポジトリ構成は以下のようになっている。

job-repo/
├── common/        ← 共通モジュール (GroupwareMailSender 等)
├── flows/
│   ├── anomaly/
│   ├── memo/
│   └── _template/

flows/ を sys.path に通しておくと、

  • from common.groupware import GroupwareMailSender のように リポジトリルート起点で書ける
  • from anomaly.scripts.xxx import yyy のように ジョブ間を跨いで参照できる

ファイルの場所（カレントディレクトリ）に依存せず import が通るようになる。

追加方法 3 種類

方法書き方いつ使う
コード内で追加sys.path.insert(0, "/flows")スクリプト自身で一時的に追加したいとき
環境変数 PYTHONPATHPYTHONPATH=/flows python ...Docker / Prefect Worker など外から指定するとき
.pth ファイルsite-packages に flows.pth を置くPython 起動時に常に有効にしたいとき

Prefect の Docker Worker なら Dockerfile で

ENV PYTHONPATH=/app/flows

と書くか、docker-compose.yml の environment: に書くのが一般的。

insert と append の違い

メソッド追加位置優先度
sys.path.insert(0, path)先頭標準ライブラリより優先される
sys.path.append(path)末尾標準ライブラリの方が優先

同名モジュールがあるときに挙動が変わるので注意。プロジェクト固有のモジュールを優先したいなら insert(0, ...)。

覚え方

  • sys.path = Python の 「モジュール探索のための住所録」
  • 追加する = 「ここも探しにいって」と住所を 1 件追記する
  • 追記しないと ModuleNotFoundError

注意点

  • パスの区切りは OS 依存。Linux/コンテナは /flows、Windows ローカルは C:\\...
  • sys.path.insert はプロセス内だけの変更。Python を再起動すると消える
  • プロジェクトで恒久的に効かせるなら PYTHONPATH か .pth を使う
  • IDE (VS Code / PyCharm) では別途 プロジェクトのソースルート設定 が必要なことがある
