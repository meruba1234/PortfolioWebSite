薄型小型カメラの機構 — 「きしめんケーブルの先にレンズ」の正体

学んだきっかけ

平たいケーブル（きしめんケーブル）の先に小さなレンズが付いたカメラを見て、「あれはどういう仕組みなのか」「既存のカメラを改造して自分で作れるのか」を知りたくなった。

結論（先に答え）

  • きしめんケーブルの正体は FPC（フレキシブルプリント基板） または FFC（フレキシブルフラットケーブル）。
  • 先端に付いているのは「レンズだけ」ではなく、レンズ + イメージセンサーが一体になったカメラモジュール。ケーブルの先で光→電気信号への変換まで終わっていて、ケーブルはデジタル信号を運んでいるだけ。
  • 自作は可能。ただし「センサーやモジュールをゼロから作る」のではなく、既製のカメラモジュールを選んで組み合わせるのが現実的な自作。スマホのカメラモジュール流用は難易度が高く、Raspberry Pi カメラや USB 内視鏡カメラの流用が入門ルート。

1. 基本構造 — カメラモジュールの解剖

スマホや薄型カメラに入っているカメラモジュールは、だいたいこの積層構造になっている。

[レンズユニット]      ← 樹脂レンズ数枚を鏡筒に積層（スマホ用で厚さ4〜6mm程度）
[IRカットフィルタ]    ← 赤外線を遮断（無いと色がおかしくなる）
[イメージセンサー]    ← CMOSセンサー。光を電気信号に変換するチップ本体
[FPC基板]            ← センサーを実装した柔らかい基板。そのままケーブル状に伸びる
[コネクタ]           ← 基板側のコネクタに挿す端子

ポイントは センサーチップが FPC に直接実装されていて、その FPC がそのまま「きしめんケーブル」として伸びていること。別々の部品をケーブルでつないでいるのではなく、モジュールとケーブルが一体成形に近い。

なぜ先端をあんなに小さくできるのか

  • CMOS センサー自体が数 mm 角しかない（スマホ用で 1/2.3型 ≒ 6×4.6mm など）。
  • レンズはプラスチック非球面レンズの積層で、焦点距離が数 mm と短い → 鏡筒も短くて済む。
  • ピント合わせを省略した固定焦点（パンフォーカス）にすれば可動部ゼロ。内視鏡カメラはほぼこれ。
  • スマホ用はオートフォーカス用に VCM（ボイスコイルモーター） でレンズを前後させるが、それでも全体で1cm角に収まる。

2. きしめんケーブル（FPC/FFC）の中を流れている信号

方式信号特徴延長の限界
MIPI CSI-2高速差動デジタルスマホ・Raspberry Piカメラの標準。高解像度・高フレームレート短い（目安 20〜30cm。それ以上はノイズで破綻）
USB (UVC)USB 2.0USB内視鏡カメラ・Webカメラ。PCに挿すだけで映る数 m まで楽に延長可
DVP（パラレル）8〜10bitパラレルESP32-CAM 等の安価モジュール（OV2640 など）短い（10cm程度）
アナログ (NTSC/AHD)アナログ映像ドローンFPV・車載バックカメラ数 m〜数十 m 延ばせる

「きしめんケーブルが長いカメラ」を見たら、中身は MIPI CSI-2 か DVP のことが多い。ケーブルを延長したいなら USB か アナログ方式が圧倒的に楽、というのが設計上の分かれ目。

3. 自作できるか？ — 難易度別ルート

ルートA: USB 内視鏡カメラの流用（入門・推奨）

  • Amazon 等で売っている USB 内視鏡カメラ（直径 5.5〜8mm、防水、LED付き、1,500〜3,000円）は、まさに「細いケーブルの先にレンズ+センサー」の完成品。
  • 中身は UVC（USB Video Class） 準拠なので、PC・Raspberry Pi・Android に挿すだけでカメラとして認識される。ドライバ不要。
  • 改造例: 外装チューブを剥いて自分の筐体に組み込む、ケーブル途中を加工する、レンズ前にマクロレンズを足す。
  • 学べること: UVC の仕組み、カメラの分解と再組み込み。

ルートB: Raspberry Pi カメラモジュール（本格・自由度高い）

  • Raspberry Pi Camera Module は MIPI CSI-2 カメラの教材として最適。モジュール単体（25×24mm、センサー部はさらに小さい）+ きしめんケーブル（FFC）そのもの。
  • Pi Zero 2 W と組み合わせれば「小型コンピュータ + 薄型カメラ」が5,000円台で組める。
  • FFC は規格品なので 長さの違うケーブルに差し替え可能（ただし30cm超は映像が乱れやすい、というMIPIの限界を体感できる）。
  • さらに小さくしたいなら Camera Module の "spy camera" 系互換品（基板を切り詰めてレンズ部だけFPCで伸ばした形状）が売られており、これが「きしめんの先にレンズ」の形に一番近い。
  • 学べること: MIPI CSI-2、libcamera、センサー設定（露出・ゲイン）、FFCの取り扱い。

ルートC: ESP32-CAM（無線化したい場合）

  • ESP32-CAM（1,000円前後）は Wi-Fi マイコン + OV2640 カメラの一体ボード。カメラ部は DVP 接続の小モジュールで、短い FPC の先にレンズが付いた形。
  • ストリーミングサーバーのサンプルコードが豊富で、「自作ネットワークカメラ」の最短ルート。
  • 学べること: DVP インターフェース、組込みでの画像処理、省電力設計。

ルートD: スマホのカメラモジュール流用（上級・基本的に非推奨）

  • ジャンクスマホからカメラモジュールを取り出すこと自体は簡単（コネクタを外すだけ）。
  • しかし動かすのが難しい:
  • MIPI CSI-2 を受けられるホスト（SoC）が必要。
  • センサーごとに専用ドライバと初期化レジスタ設定が必要で、データシートが NDA で入手不可のことが多い。
  • ISP（画像処理プロセッサ）側の調整（デモザイク、ホワイトバランス）も自前。
  • Raspberry Pi で動く実績のあるセンサー（IMX219, OV5647 等）以外は、個人ではほぼ詰む。「既存カメラの改造」はスマホよりWebカメラ・内視鏡カメラを素材にする方が筋が良い。

ルートE: Webカメラの分解改造（中級・実用的）

  • 安いUSB Webカメラを分解すると「基板 + 短いFPC + レンズ/センサー部」に分かれるものがある。
  • レンズはねじ込み式（M12マウント / S-mount）のことが多く、レンズだけ交換（広角化・狭角化）が簡単にできる。
  • 基板とセンサー部が分離しているタイプなら、FPC延長ケーブルを足して「基板は手元、レンズ先端だけ細い場所へ」という構成が作れる。

4. 自作するときの設計判断フローチャート

ケーブルを1m以上延ばしたい？
 ├─ Yes → USB (UVC) かアナログ方式を選ぶ（ルートA/E）
 └─ No（30cm以内でOK）
     ├─ 画質重視・Linuxで処理したい → Raspberry Pi + CSIカメラ（ルートB）
     ├─ 無線で飛ばしたい → ESP32-CAM（ルートC）
     └─ とにかく細く小さく → 内視鏡カメラ流用（ルートA）

5. 工作時の実務知識

  • FPC/FFC は折り曲げ厳禁。曲げRは緩く取る。一度折り目が付くと内部の銅箔が断線する。きしめんケーブルが「ゆるく湾曲」して取り回されているのはこのため。
  • FFC コネクタは フリップロック式（黒いラッチを起こして挿入→倒して固定）。ラッチを起こさず無理に挿すとコネクタが壊れる。
  • ケーブルには表裏がある（端子面の向き）。Raspberry Pi 公式カメラは「端子面をどちらに向けて挿すか」をよく間違えるポイント。
  • 静電気に弱い。センサー面・端子面は素手で触らない。
  • レンズとセンサーの距離（フランジバック）が数十 µm ズレるだけでピントが崩れる。レンズユニットを分解したら元のピント位置に戻すのは難しいと心得る。

6. 法律・モラルの注意

小型カメラは便利な反面、撮影場所・用途によっては盗撮規制（撮影罪・各都道府県の迷惑防止条例）やプライバシー侵害に直結する。自作・改造の目的は工作技術の学習や自分の所有物の監視（3Dプリンタ監視、ペットカメラ、機器内部の点検等）に限定し、人を無断で撮影する用途には絶対に使わないこと。
