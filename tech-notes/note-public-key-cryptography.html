セキュリティ

公開鍵暗号とデジタル署名

学んだきっかけ

Windows Update KB5083769 (2026-04) により、RDPファイル接続時にセキュリティ警告が表示されるようになった。対策としてRDPファイルにデジタル署名を付与する作業を通じて、公開鍵暗号の仕組みを学んだ。

公開鍵暗号とは

暗号化と復号に「異なる2つの鍵」を使う方式。

  • 秘密鍵（Private Key） — 本人だけが持つ鍵。絶対に外部に漏らしてはいけない。
  • 公開鍵（Public Key） — 誰にでも配布できる鍵。配布しても安全。

この2つは数学的にペアになっており、片方で暗号化したものはもう片方でしか復号できない。

身近な例え

暗号の世界身近な例え
秘密鍵実印（本人だけが持つ）
公開鍵印鑑証明書（役所に届け出て誰でも照合できる）
署名済みファイル実印が押された契約書
証明書のインストール「この印鑑証明書を信頼する」と登録すること

デジタル署名の仕組み

署名する側（管理者）

ファイルの内容 → ハッシュ値を計算 → 秘密鍵で暗号化 → 署名データ

検証する側（利用者）

署名データ → 公開鍵で復号 → ハッシュ値を比較 → 一致すれば「改ざんなし＋信頼できる発行元」

再署名が必要になる理由

署名データの正体は「ファイルの中身のハッシュ値を秘密鍵で暗号化したもの」。

  • ファイルの中身が1文字でも変わる → ハッシュ値が変わる
  • 古い署名データのハッシュ値と一致しなくなる → 「改ざんされた」と判定される
  • だから同じ秘密鍵で新しい署名データを作り直す = 再署名

再署名で変わるもの： 署名データだけ 変わらないもの： 秘密鍵、公開鍵、証明書すべてそのまま

印鑑で例えると、契約書の内容を書き換えたら、同じ実印でもう一度押し直すのと同じ。

CA（Certificate Authority / 認証局）とは

CA = Certificate Authority（認証局） — 証明書を発行する権限を持つ機関。

自己署名 vs CA発行 の違い

自己署名証明書CA発行の証明書
作成PowerShell 1行で即作成認証局に申請、審査、費用あり
信頼性自分で「自分は信頼できる」と言っているだけ第三者機関が身元を保証
社外への効力なしあり
社内利用配布すれば十分オーバースペック
CAサーバー不要必要（外部CAまたは社内CA）

自己署名証明書のポイント

  • 作ること自体は誰でもできる（「私は○○です」と自称しているだけ）
  • 各PCにインストールして初めて信頼される
  • 外部の誰かが同じ名前で証明書を作っても、インストールしない限り信頼されない

CAサーバー（AD CS）が必要になるケース

社内でCAサーバーを立てる = Active Directory証明書サービス（AD CS）を使う。

CAサーバーが必要な場面：

  • 社内で大量の証明書を発行・管理したいとき（例：全社員にクライアント証明書を配布）
  • Wi-Fiの802.1X認証（証明書ベースのネットワーク認証）
  • 社内WebサーバーのSSL証明書を自前で発行
  • VPNの証明書認証

CAサーバーなしでできること：

  • Active Directoryのユーザー管理、GPO → CAなしで動く
  • 自己署名証明書の発行 → PowerShellだけでOK

Active Directory と CA の関係

  • ADはCAサーバーなしでも使える（ユーザー管理、GPO配布など）
  • CAサーバーはADの必須コンポーネントではない
  • 「証明書を組織的に大量管理する」必要が出たときに初めてCAサーバーを検討する

証明書ファイルの種類

拡張子中身用途
.cer公開鍵のみ配布用。誰に渡しても安全
.pfx秘密鍵＋公開鍵バックアップ用。パスワード保護。厳重管理

証明書の保管場所（Windows）

  • certmgr.msc（証明書マネージャー）→「個人」→「証明書」に秘密鍵付きで保管
  • 資格情報マネージャー（ID/パスワード）とは別物

実際にやったこと（RDP署名の例）

  1. PowerShellで自己署名証明書を作成（New-SelfSignedCertificate）
  2. rdpsign コマンドでRDPファイルに署名
  3. 公開鍵（.cer）を各PCの「信頼された発行元」にインストール
  4. 署名済みRDPファイルを配布

→ セキュリティパッチ適用後も警告なしでRDP接続が可能になった

関連コマンド

# 自己署名証明書の作成
New-SelfSignedCertificate -Subject "CN=名前" -Type CodeSigningCert -CertStoreLocation "Cert:\CurrentUser\My" -NotAfter (Get-Date).AddYears(10)

# RDPファイルに署名
rdpsign /sha256 <Thumbprint> "ファイル.rdp"

# 証明書のエクスポート（公開鍵のみ）
Export-Certificate -Cert $cert -FilePath "output.cer"

# 証明書のエクスポート（秘密鍵付き）
Export-PfxCertificate -Cert $cert -FilePath "output.pfx" -Password $password
