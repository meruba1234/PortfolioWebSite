ネットワーク

RDPとRemoteAppの認証情報・負荷分散の仕組み

学んだきっかけ

販売管理システム（RemoteApp + 負荷分散環境 + 署名済みRDP）で、毎回ログイン情報を聞かれる問題に遭遇。資格情報マネージャーに保存されているのに使われない理由を調べる過程で、Windows資格情報と汎用資格情報の違い、RDPとRemoteAppの違いを学んだ。

Windows資格情報 vs 汎用資格情報

どちらもWindows資格情報マネージャー（control /name Microsoft.CredentialManager）で管理されるが、使われ方が違う。

Windows資格情報汎用資格情報
目的OSの認証（Kerberos/NTLM）、自動SSOアプリが明示的に使う
使う側Windowsサービス、共有フォルダ、従来型RDPカスタムアプリ、RemoteApp、VPNクライアント等
参照APILsaLogonUser（OS内部）CredRead/CredWrite（アプリから明示）
登録コマンドcmdkey /add:ターゲット /user:... /pass:...cmdkey /generic:ターゲット /user:... /pass:...

安全な運用

両方に登録しておくのが最も安全。どちらの認証経路でもヒットするので、Windowsの挙動変更にも対応可能。

cmdkey /add:TERMSRV/server /user:DOMAIN\user /pass:password
cmdkey /generic:TERMSRV/server /user:DOMAIN\user /pass:password

RDPとRemoteAppの違い

RDP（リモートデスクトップ）

  • リモートコンピューターのデスクトップ画面全体を表示
  • Windowsのデスクトップを丸ごと操作する感覚
  • 主にWindows資格情報を参照

RemoteApp

  • リモートで特定のアプリだけを起動
  • ローカルのウィンドウとして表示される（デスクトップは見えない）
  • .rdpファイルで remoteapplicationmode:i:1 が設定されている
  • 起動するアプリは alternate shell:s:||アプリ名 で指定
  • 汎用資格情報を優先的に参照

RDPファイルでの見分け方

remoteapplicationmode:i:1       # RemoteApp有効
alternate shell:s:||Login        # 起動するアプリ
remoteapplicationprogram:s:||Login
remoteapplicationname:s:Login

これらが設定されていたら RemoteApp モード。

負荷分散環境での資格情報

接続の仕組み

ユーザー
  ↓
<broker-ip>（ブローカー／ロードバランサー）
  ↓ セッション振り分け
<host1>.<internal-domain> または
<host2>.<internal-domain> または
<host3>.<internal-domain> または
<host4>.<internal-domain>（実際の接続先セッションホスト）

キーとなる設定

full address:s:<broker-ip>       # 入り口のブローカー
use redirection server name:i:1  # リダイレクト先の名前を使う

use redirection server name:i:1 が有効だと、ブローカーから実際のホストに振り分けられる。

資格情報登録の注意

各セッションホストごとに資格情報が必要。ブローカーのアドレスだけ登録しても、実際の接続先ホストで認証を求められる。

登録すべきエントリ例：

TERMSRV/<broker-ip>                  # ブローカー
TERMSRV/<cluster>.<internal-domain>  # クラスター名
TERMSRV/<host1>.<internal-domain>    # 個別ホスト
TERMSRV/<host2>.<internal-domain>
TERMSRV/<host3>.<internal-domain>
TERMSRV/<host4>.<internal-domain>

KB5083769適用後の挙動変化

セキュリティパッチ適用で、署名済みRDP + RemoteApp の組み合わせで認証経路が変化した可能性がある。結果として：

  • Windows資格情報だけでは認証が通らない
  • 汎用資格情報にも同じ内容を登録する必要がある
  • 接続先が負荷分散で変わるため、各ホスト分を登録する必要がある

実用例：一括登録スクリプト

$user = "<DOMAIN>\<user>"
$pass = "password"
$servers = @(
    "<broker-ip>",
    "<cluster>.<internal-domain>",
    "<host1>.<internal-domain>",
    "<host2>.<internal-domain>",
    "<host3>.<internal-domain>",
    "<host4>.<internal-domain>"
)

foreach ($s in $servers) {
    # 汎用資格情報
    cmdkey /generic:"TERMSRV/$s" /user:$user /pass:$pass | Out-Null
    # Windows資格情報
    cmdkey /add:"TERMSRV/$s" /user:$user /pass:$pass | Out-Null
}
