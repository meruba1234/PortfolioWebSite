2026年10月27日時点の公式発表とMicrosoft公式資料を基にした個人学習記事です。進行中の事案について、公式確認済み事項と一般的な技術解説を分けて記載しています。

WindowsRDPセキュリティ

RDPのドライブ共有はなぜ危険か

侵害済み接続先からローカルPCを守るために、ドライブリダイレクト、高権限アカウント、セッション失効の関係を整理します。

確認済み事実と技術的仮説を分ける

2026年10月24日の「お名前.com デスクトップクラウド」公式発表では、一部の利用者サーバーへの不正プログラム設置、サーバー内の取引口座ログイン情報などが取得・不正利用された可能性、影響の可能性があるサーバー26,739件が公表されました。この件数は侵害確認件数ではなく、対象となり得る件数です。

顧客PCへの具体的な侵入経路は調査中です。ここでは事件の原因を断定せず、RDPの一般仕様としてローカル資源が接続先から利用可能になる条件を扱います。

RDPは画面転送だけではない

RDPは、設定によってローカルドライブ、クリップボード、プリンターなどを接続先へ共有できます。Microsoftは、ドライブリダイレクトを許可すると、リモートコンピューターがローカルドライブ上のファイルを読み書きできると説明しています。

接続先サーバーが侵害済み
  + 利用者がRDP接続中
  + ドライブ共有が有効
  + 攻撃者がそのセッションを悪用可能
  = ローカルファイルへ到達する経路が生じ得る

接続先からは、環境によって\\tsclient\Cのような名前で手元PCのドライブが見えます。Cドライブをインターネット全体へ公開する仕組みではなく、RDPセッション内の仮想チャンネルを通じてファイル操作を要求します。

暗号化だけでは止められない

RDP通信の暗号化は、経路上の盗聴や改ざんを防ぐために重要です。しかし、接続先そのものが侵害されている場合、暗号化は接続先からのファイル操作を止めません。

「通信経路を守ること」と「接続先を信頼できる状態に保ち、共有範囲を最小化すること」は別々に必要です。

ADとラテラルムーブメント

Active Directoryは、組織内のユーザー、端末、グループ、権限を管理する仕組みです。問題はADそのものではなく、高権限アカウントの利用範囲が広すぎる場合です。

1台の侵害
  → 高権限資格情報の取得
  → 管理可能な別サーバーへ移動
  → 業務・顧客環境へ被害が拡大

Microsoftは、Domain Adminsなどのメンバーを最小限にし、管理者アカウントと通常アカウントを分け、管理者がサインインできる端末を制限することを推奨しています。

パスワードとセッションは別物

パスワード変更後も、認証済みの既存セッションが直ちに失効するとは限りません。公式案内でも、パスワード変更済みの場合を含め、接続中の全セッションを切断するよう案内されています。

  • 資格情報を変更する
  • 既存セッションとトークンを失効させる
  • 多要素認証を有効化する
  • ログイン履歴・取引履歴を確認する
  • 端末とサーバーを調査する

利用者側の対策

  1. 不要なドライブ共有とクリップボード共有をオフにする
  2. RDPファイルの接続先・発行元・共有項目を確認する
  3. 侵害が疑われたらパスワード変更と全セッション切断を行う
  4. 端末をフルスキャンし、重要データを安全な場所へバックアップする
  5. メール内リンクではなく、事業者の公式サイトから最新情報を確認する

管理者側の対策

  • 特権グループのメンバーを最小限にする
  • 日常利用と管理作業でアカウントを分ける
  • 管理者のログオン先を管理端末へ限定する
  • 顧客・管理・通常業務のネットワークを分離する
  • 不要なRDPリダイレクトをグループポリシーで禁止する
  • 管理者ログオンとサーバー間通信を監視する

今回の学び

  • クラウドに保存したデータだけでなく、クラウドへ接続・共有した資源も保護対象になる
  • 暗号化は重要だが、侵害済みの接続先を安全には戻さない
  • ADでは権限の広さと運用方法が被害範囲を左右する
  • パスワード変更とセッション失効は別の作業
  • 公式確認済み事項と技術的仮説を分けて読む
